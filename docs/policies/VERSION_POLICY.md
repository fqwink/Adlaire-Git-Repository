# バージョンポリシー

**位置づけ**: 2類責務別ポリシー
**責務**: バージョン表記、累積方式、Major / Minor 更新条件
**ステータス**: 初期策定

---

## 1. バージョン表記

本プロジェクトの正式バージョンは、以下の形式で表記する。

```text
v.{Major}.{Minor}
```

例:

```text
v.0.1
v.1.12
v.2.23
v.12.150
```

## 2. 累積方式

`Major` は累積フェーズ番号として扱う。

`Minor` はプロジェクト全体で累積する変更番号として扱う。

フェーズ番号、`Major`、`Minor` は、いずれもリセットしてはならない。

## 3. Major の扱い

Major バージョンは安定版リリースの扱いと関係する。

安定版リリースとして扱う `Major` は、Phase 7、Phase 17、Phase 27 のような 7系フェーズをデフォルト方針とする。

5系・9系フェーズは補助的なリリース判定フェーズとし、ユーザー承認がある場合のみケースバイケースで安定版リリースフェーズとして扱う。

## 4. Minor の更新条件

以下のいずれかに該当する場合、`Minor` を更新する。

- 後方互換を維持した機能追加
- 既存機能の機能改良
- バグ修正
- セキュリティ修正
- ドキュメント更新
- テスト追加、検証修正
- 既存仕様を変えない内部整理
- CI/CD、開発環境、リリース手順の修正
