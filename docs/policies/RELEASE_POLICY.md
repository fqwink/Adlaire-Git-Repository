# リリースポリシー

**位置づけ**: 2類責務別ポリシー
**責務**: 安定版リリース、リリース対象、リリース禁止条件
**ステータス**: 初期策定

---

## 1. リリース対象

本プロジェクトで正式にリリース対象とするものは、安定版リリースのみとする。

バージョン `v.0.x` 系は、初回安定版リリース前の開発・検証段階として扱い、正式な安定版リリース対象ではない。

安定版リリースとして扱うバージョンは、バージョンポリシーに基づき `Major` が `1` 以上の系列とする。

安定版リリースフェーズは、Phase 7、Phase 17、Phase 27 のような 7系フェーズをデフォルト方針とする。

5系フェーズは補助的なリリース判定、設計・デザイン改良、仕様整理のためのフェーズとし、安定版リリースフェーズとして扱わない。

6系フェーズは、大規模なバグ修正とドキュメント整合性向上をデフォルト方針とする安定版リリース準備フェーズとする。必要に応じて移行準備と検証強化も行う。6系フェーズ自体は安定版リリースフェーズとして扱わない。

9系フェーズは補助的なリリース判定フェーズとする。9系フェーズは、マスター開発計画と2類ポリシーに明記し、ユーザー承認を得た場合のみ、ケースバイケースで安定版リリースフェーズとして扱う。

## 2. リリース禁止条件

以下に該当する場合、リリースしてはならない。

- 既知のバグが残っている。
- セキュリティ要件の検証が未完了である。
- 主要仕様に対する意味のあるテストまたは代替検証による確信を説明できない。
- 3類マスター仕様書と実装が矛盾している。
- バージョン表記がバージョンポリシーに従っていない。
- ライセンス方針が未確認である。
- 安定版リリースとして判定されていない。
- リリース提案、配置先、成果物、検証方法、承認範囲が未提示である。
- ユーザー承認を得ていない。

## 3. 安定版以外の扱い

以下は正式リリース対象に含めない。

- 開発中バージョン
- 検証版
- 内部確認版
- 試験的実装
- 仕様未確定の暫定版
- 既知バグが残る版

## 4. リリース提案

リリース作業を行う前に、必ずリリース提案を提示し、ユーザー承認を得る。

リリース提案には、最低限以下を含める。

- 対象バージョン
- 対象フェーズ
- リリース理由
- リリース成果物
- リリース配置先
- 検証方法
- 承認後に自動実行する範囲

リリース提案を提示せずに、tag 作成、GitHub Releases 作成、成果物配置、release notes 公開、`main` 反映を行ってはならない。

## 5. リリース配置

リリース成果物の主配置は GitHub Releases とする。

GitHub Releases には、リリースごとの成果物、release notes、必要な checksum、manifest を配置する方針とする。

リポジトリ内には、リリース配置記録、release notes の元資料、manifest、checksum、運用手順など、履歴として追跡すべき軽量なリリース関連ファイルを配置できる。

大きなバイナリ成果物をリポジトリへ継続的に直接配置してはならない。大きな成果物は GitHub Releases を優先する。

リポジトリ内の配置先は、必要になった時点で提案し、ユーザー承認を得て決定する。候補は `docs/releases/` または `releases/` とする。

## 6. リリース自動化

リリース作業は、承認工程を省略しない範囲で自動化を推奨する。

本番サーバ環境へのデプロイ、デプロイ前後の検証、バックアップ、ロールバックは `docs/policies/DEPLOYMENT_POLICY.md` を正本とする。リリース自動化とデプロイ自動化を同時に扱う場合も、承認対象、成果物、検証範囲、失敗時対応を分けて提示する。

ユーザー承認後に限り、以下を自動実行してよい。

- Git tag 作成
- GitHub Releases 作成
- 成果物アップロード
- checksum 生成
- manifest 生成
- release notes 反映
- Pull Request 更新

自動化する場合も、対象バージョン、対象フェーズ、配置先、成果物、検証方法、自動実行範囲を事前に提示し、ユーザー承認を得なければならない。

## 7. 別承認が必要なリリース作業

以下は、リリース自動化の対象としてまとめて扱わず、必ず別途承認を得る。

- 初回安定版リリース判定
- 安定版リリースとしての公開判断
- `main` 反映
- Pull Request merge
- リモートまたはローカル作業ブランチ削除
- リリース配置先の新規決定または変更
- 公開済みリリースの削除
- 公開済み tag の削除または付け替え
