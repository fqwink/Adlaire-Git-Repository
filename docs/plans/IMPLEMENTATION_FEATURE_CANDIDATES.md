# 実装機能候補リスト

**位置づけ**: マスター開発計画補助ドキュメント
**対象**: Auris / Adlaire Git Repository
**文書バージョン**: v.0.1
**ステータス**: 候補整理中

---

## 1. 目的

本書は、今後の実装機能候補を種別ごとに整理するための補助ドキュメントである。

基本的な機能互換は GitHub 互換基準とし、オープンソース Git プロバイダーはサブの機能互換インスパイア対象として扱う。

ただし、GitHub や OSS Git プロバイダーに存在する機能であっても、現時点で不要な機能は実装対象から除外する。

本書は候補整理であり、実装承認ではない。実装対象へ確定する場合は、3類マスター仕様書、マスター開発計画、検証範囲へ反映し、ユーザー承認を得る。

---

## 2. 選定基準

実装候補は、以下の基準で判断する。

- 内部向け Git ホスティング基盤として日常開発に必要か
- GitHub の基本的な機能互換として重要か
- Phase 2 以降の開発計画に収まるか
- セキュリティ、権限管理、監査に必要か
- 外部依存や運用負荷が過度に増えないか
- UI 互換ではなく、本プロジェクト独自 UI として実装できるか

## 3. 優先実装候補

### 3.1 レビュー・変更管理

| 機能 | 種別 | 理由 |
|---|---|---|
| Pull Request | 優先 | ブランチ間の変更提案、差分確認、マージ判断の中心機能であるため |
| Code Review | 優先 | Pull Request に対するコメント、承認、変更要求を扱う品質管理の基本機能であるため |

### 3.2 課題管理

| 機能 | 種別 | 理由 |
|---|---|---|
| Issue | 優先 | バグ、タスク、要望をリポジトリ単位で管理する基本機能であるため |

### 3.3 ドキュメント管理

| 機能 | 種別 | 理由 |
|---|---|---|
| Wiki | 優先 | リポジトリ単位の仕様、運用手順、補足資料を管理できるため |

### 3.4 連携・自動化

| 機能 | 種別 | 理由 |
|---|---|---|
| Webhook | 優先 | 外部通知、内部ツール連携、将来の自動化の土台になるため |
| REST API 基本機能 | 優先 | 内部ツールや運用スクリプトから利用できる基本連携口になるため |

### 3.5 リリース管理

| 機能 | 種別 | 理由 |
|---|---|---|
| Release 管理 | 優先 | tag、リリースノート、成果物管理を整理でき、バージョン方針と相性がよいため |

### 3.6 リポジトリ管理

| 機能 | 種別 | 理由 |
|---|---|---|
| Repository settings 拡張 | 優先 | visibility、default branch、保護設定など運用に必要な管理項目を扱うため |

### 3.7 権限・監査

| 機能 | 種別 | 理由 |
|---|---|---|
| 権限管理強化 | 優先 | private repository、merge、Issue 編集、Wiki 編集などの操作制御に必要なため |
| 監査ログ拡張 | 優先 | 内部向け基盤として、誰が何をしたか追跡できることが重要であるため |

## 4. 保留候補

### 4.1 ソーシャル・通知補助

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Star / Watch | 保留 | 内部向け基盤では必須度が低く、通知設計と合わせて検討する必要があるため |

### 4.2 プロジェクト・コミュニケーション

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Projects | 保留 | Issue 実装後に価値が出る機能であり、初期優先度は下げるため |
| Discussions | 保留 | Issue と Wiki で当面代替できるため |

### 4.3 組織管理

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Organizations / Teams 本格運用 | 保留 | 権限設計が重く、まずは単純なユーザー、管理者、collaborator を優先するため |

### 4.4 外部連携・同期

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Mirror repository | 保留 | 外部 Git サービス連携、認証情報管理、同期失敗時の扱いを整理する必要があるため |

### 4.5 検索・解析

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Code search | 保留 | 検索インデックス、性能、ストレージ設計が必要であり、小規模運用では後回しにできるため |

### 4.6 パッケージ・成果物配布

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Package registry | 保留 | Git ホスティング本体から外れ、容量管理、認証、配布設計が重いため |
| Container registry | 保留 | Git ホスティング本体から外れ、ストレージ、セキュリティ、運用負荷が大きいため |

### 4.7 CI / ホスティング

| 機能 | 種別 | 保留理由 |
|---|---|---|
| CI / Actions 互換 | 保留 | 実行環境、権限分離、ジョブ隔離、セキュリティ設計が重いため |
| Pages 相当 | 保留 | 静的ホスティング機能であり、Git ホスティング本体の優先度より低いため |

### 4.8 高度機能

| 機能 | 種別 | 保留理由 |
|---|---|---|
| Advanced Security | 保留 | 脆弱性DB、依存関係解析、スキャン基盤など外部依存や運用負荷が大きいため |
| Copilot 相当 | 保留 | AI 機能であり、現時点の Git ホスティング基盤コアから外れるため |
| Federation | 保留 | 内部向け基盤では現時点の必要性が低く、運用モデルも大きく変わるため |

## 5. Phase 2 推奨範囲

Phase 2 の推奨実装範囲は、以下に絞る。

- Pull Request
- Code Review
- Issue
- Wiki
- Webhook
- Release 管理
- REST API 基本機能
- Repository settings 拡張
- 権限管理強化
- 監査ログ拡張

Star / Watch は Phase 2 の優先実装候補には含めず、保留候補として扱う。
