# 開発ポリシールールブック

**対象**: `{PROJECT_NAME}`
**位置づけ**: 2類ポリシー総則
**責務**: 2類ポリシー群の総則、共通原則、参照順序、変更手順

---

## 1. 基本原則

- `AGENTS.md` は絶対原則である。
- 2類ポリシーは `AGENTS.md` に違反してはならない。
- 3類マスター仕様書は仕様の正本である。
- 変更を加える作業では、承認工程を省略してはならない。
- 本番サーバ環境へのデプロイは、承認工程を省かず、バックアップ、検証、ロールバック前提を含めて自動化を標準とする。
- `{PRIMARY_BRANCH}` への直接 push は禁止する。
- すべての変更は Pull Request 経由で取り込む。

---

## 2. 2類ポリシー群

| ポリシー | 責務 |
|---|---|
| `DOCUMENT_CHARTER.md` | ドキュメント体系、責務境界、改訂単位 |
| `TECHNICAL_REQUIREMENTS_POLICY.md` | 技術要件、採用技術、固定バージョン |
| `VERSION_POLICY.md` | バージョン表記、更新条件 |
| `RELEASE_POLICY.md` | リリース対象、配置、公開判断 |
| `TEST_POLICY.md` | テスト方針、検証条件 |
| `LICENSE_POLICY.md` | ライセンス、権利帰属、配布条件 |
| `SECURITY_POLICY.md` | セキュリティ、認証、脆弱性対応 |
| `DATA_POLICY.md` | データ、保存、移行、削除、バックアップ |
| `DEPENDENCY_POLICY.md` | 外部依存、レジストリ、例外採用 |
| `DEPLOYMENT_POLICY.md` | デプロイ、運用基盤、環境管理、バックアップ、検証、ロールバック |

---

## 3. 承認前提示

変更前に最低限以下を提示する。

- 変更対象
- 変更理由
- 変更案
- 影響範囲
- 検証方法
- 承認後に自動実行する範囲

提示なしに編集、削除、移動、生成、stage、commit、push、Pull Request 作成または更新を行ってはならない。

---

## 4. 承認後の自動化

ユーザー承認後に限り、承認済み範囲の編集、検証、stage、commit、push、Pull Request 作成または更新を自動実行してよい。

承認済み範囲を超える変更、Pull Request merge、`{PRIMARY_BRANCH}` 反映、作業ブランチ削除、破壊的 Git 操作は、必ず別途承認を得る。
