## 0. 絶対原則

`AGENTS.md` 自体が、`{PROJECT_NAME}` における絶対原則である。

すべての作業者は、調査、設計、ドキュメント改訂、実装、検証、Git 操作、Pull Request 作成、レビュー対応、リリース判断を含む全作業において、必ず最初に `AGENTS.md` を読む。

`AGENTS.md` を読んだ後、`docs/DOCUMENT_INDEX.md` を参照索引として確認し、作業に必要な2類ポリシー、3類マスター仕様書、計画文書を読む。

`docs/DOCUMENT_INDEX.md` は参照索引であり、`AGENTS.md`、2類ポリシー、3類マスター仕様書の代替ではない。

## 1. 最上位ドキュメント体系

最上位ドキュメントは、1類、2類、3類に分類する。

| 類 | 位置づけ | 役割 |
|---:|---|---|
| 1類 | ルールブック | 絶対原則、禁止事項、優先順位、承認義務、作業手順を定義する |
| 2類 | ポリシー | 開発、運用、品質、リリース、セキュリティ、ライセンス等の責務別方針を定義する |
| 3類 | マスター仕様書 | プロダクト仕様、システム仕様、機能仕様、非機能仕様を定義する |

1類は最上位であり、2類および3類より常に優先する。

---

## 2. ルールブックとポリシーの役割

`AGENTS.md` は、全作業に適用される絶対原則、禁止事項、優先順位、承認義務、上位参照順序を定義する。

2類ポリシーは、`AGENTS.md` に従う下位文書として、責務別方針、判定条件、運用手順を定義する。

`AGENTS.md` と2類ポリシーの役割を混同してはならない。責務別の詳細条件、判定基準、手順、例外管理は、該当する2類ポリシーを正本として定義する。

## 3. 承認原則

変更を加える作業では、承認工程を省略してはならない。

変更前に必ず、変更対象、変更理由、変更案、影響範囲、検証方法を提示し、ユーザー承認を得る。

承認後に限り、承認済み範囲の編集、検証、承認済み範囲だけの stage、commit、push、Pull Request 作成または更新を自動実行してよい。

承認済み範囲を超える変更、方針の意味変更、ソースコード実装、依存関係・技術採用・バージョン固定、Pull Request merge、`{PRIMARY_BRANCH}` 反映、作業ブランチ削除、破壊的 Git 操作は、必ず別途承認を得る。
