# ドキュメント憲章

**対象**: `{PROJECT_NAME}`
**位置づけ**: 2類ドキュメント憲章
**責務**: ドキュメント体系、責務境界、改訂単位

---

## 1. 基本方針

本憲章は、`{PROJECT_NAME}` におけるドキュメント体系、責務境界、改訂単位の扱いを定義する。

`AGENTS.md` は1類ルールブックであり、絶対原則、禁止事項、優先順位、承認義務、作業手順を定義する。

2類ポリシーは、`AGENTS.md` に従う下位文書として、責務別方針、判定条件、運用手順を定義する。

3類マスター仕様書は、仕様の正本である。

`docs/DOCUMENT_INDEX.md` は参照索引であり、正本ではない。

`docs/tpl-governance/` は、AdlaireGroup 共通ガバナンス雛形の正本である。各プロジェクトの運用正本とは分離し、共通方針の展開元として管理する。

---

## 2. 読了義務

すべての作業では、必ず最初に `AGENTS.md` を読む。

その後、`docs/DOCUMENT_INDEX.md` を索引として、作業に必要な2類ポリシー、3類マスター仕様書、計画文書を読む。

最上位ドキュメントを読む工程では、直前作業の Pull Request merge 状態、作業ブランチのクローズ状態、ローカルとリモートの整合性を同時に確認する。

未読、部分読了、過去に読んだ記憶、前回作業時の要約だけを根拠に、読了義務を満たしたと扱ってはならない。

---

## 3. 責務境界

1類、2類、3類、計画文書、利用者向け文書の責務を混同してはならない。

責務が混同されている場合は、内容の責務を判定し、該当する正本へ移して整合させる。

採用技術、固定バージョン、ライセンス、デプロイ方式、データ保存、依存関係、セキュリティ要件は AdlaireGroup 共通方針として扱う。

プロジェクト名、プロダクト名、仕様書名、配置先、サーバ名、ドメイン、Phase 計画、実装対象機能は、共通方針を破らない範囲で各プロジェクトが具体化する。

---

## 4. 整合性確認

ドキュメント整合性は、1類ルールブック、2類ポリシー、3類マスター仕様書、計画文書、README、実装、テスト、検証導線、バージョン表記、Pull Request 説明を含む全体へ適用する。

矛盾が残る場合は、作業完了として扱ってはならない。

---

## 5. 共通雛形との同期

各プロジェクトのルール、ポリシー、技術方針、ライセンス、デプロイ、データ、依存関係、セキュリティを変更する場合は、`docs/tpl-governance/` の更新要否を判定する。

AdlaireGroup 共通方針に該当する変更は、同一変更範囲で共通雛形へ反映する。

プロジェクト固有仕様に限定される変更は、共通雛形へ反映しない。
